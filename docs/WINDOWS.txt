LAN 测速 1.3.7 Windows 版

1. 解压完整压缩包，运行 lan_iperf.exe。保留所有 DLL、iperf3.exe、data 和 licenses。
   “本机连接信息”每 3 秒刷新连接类型和发送/接收链路速率；Wi-Fi 显示信号、频段、信道和标准。
   速率来自网卡驱动，不是实测吞吐量；多网卡分别显示，实际测速路径由系统路由选择。
   未提供的信息显示“系统未提供”；Wi-Fi 详情受限时，请按提示在 Windows 设置中允许位置访问。
   启动自动开启服务端，默认端口 5201；可修改端口并重启服务端。
   正常关闭或主程序异常结束都会清理自己启动的服务端进程。

2. 两端打开新版软件，在一端搜索并选择另一端，再“开始测速”。
   方向可选“先下载后上传”（默认）、“只下载”、“只上传”，自动保存选择。
   顺序模式每阶段使用设定时长，例如 10 秒为下载 10 秒，再上传 10 秒。
   时长可设 1–99999 秒；超过 86400 秒自动续接下一段会话，短暂切换后继续，曲线与统计合并。
   安卓与 PC 默认端口均为 5201；本版升级首次启动会恢复旧监听端口到 5201，此后可自行修改保存。
   下载阶段不显示上传线和上传图例，进入上传阶段才显示；旧版顺序记录同样生效。
   保留两阶段曲线与各自平均速度，真实统计每 0.1 秒更新。
   多连接开关关闭为每方向 1 路，开启默认 4 路，可调到 16 路。
   Windows 多连接采用工作线程；安卓引擎在单线程内处理多连接。

3. “恒定负载测延迟”：选择只上传或只下载，默认只下载，仅选定方向使用总目标 Mbps。
   记住该模式的方向选择；关闭该模式后恢复普通测速的原选择。
   多连接自动分摊目标速率，实际带宽仍受链路能力影响。
   图中绿色上传、蓝色下载、橙色 TCP 延迟（右轴毫秒）。
   “静态延迟测试”持续做 TCP 连接探测，直到点击“停止测试”或关闭软件，不发送 iperf3 带宽负载。
   实时图表按实际时间显示，超过 60 秒滚动展示最近一分钟，不按预设总时长压缩。
   静态测试只画延迟，保留最近 1200 个样本，平均/最低/最高和失败次数累计整个测试。
   默认间隔 0.1 秒；超时会延长总时长，可随时停止。
   延迟是连接目标端口的耗时（含调度），不是 ICMP ping。

4. 其他设备开始测速时，服务端显示对方 IP、连接提示和实时上下行曲线。
   本机发送为上传，接收为下载。结束后保留本次曲线。
   服务端曲线不显示客户端测量的 TCP 延迟。仅搜索设备不会触发测速提示。

5. 支持手动添加 IPv4、IPv6 和主机名。IPv6 不加方括号，端口另填。
   自动搜索只支持 IPv4。IPv6 需要系统启用、两端路由可达并放行防火墙。

6. 防火墙首次提示时允许 iperf3 的“专用网络”。TCP 放行对应 TCP 端口，UDP 另外放行 UDP 端口。
   软件不会自行更改防火墙规则。安卓请保持软件打开，后台/锁屏服务不保证持续运行。

已知限制：Windows Cygwin 服务端不可靠地支持 UDP 双向/多流，这是上游问题。
普通单连接 UDP“先下载后上传”已通过本机验证。UDP 多连接/双向建议使用 TCP 或兼容的 Linux/安卓服务端。
启动 8 秒未收到数据会停止并显示原因。
https://github.com/esnet/iperf/issues/1992

Windows x64 Release；安卓包为开发签名测试版。
Windows 已验证 IPv4/IPv6 TCP 双向、多连接、恒定负载并发延迟及退出清理。
安卓三架构已编译，未做真机运行验证。
